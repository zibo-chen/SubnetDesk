# 分组与可变连接地址

本轮将用户选定的第一版方案落到 Flutter 桌面设备页。附近、最近、收藏和全部来源共用侧栏、搜索区、表格与分页，切换来源不替换布局；分组勾选仅在收藏来源启用，其他来源保留相同占位。设备记录、收藏、分组和已保存设备的连接入口统一使用小写 SHA-256 公钥指纹；IP、端口、主机名与显示名称都是记录属性。没有指纹的旧收藏保留为待确认连接目标，不能新建分组关联或新增为正式收藏。

## 分组

收藏页使用左侧分组目录和右侧设备表格，支持分组搜索、范围明确的设备搜索、可达状态过滤、每页 12 台、当前页全选、跨页勾选和批量移动。移动弹窗可搜索目标组，预览数量变化，批量操作只写一次分组配置，并提供撤销。新建、重命名和删除沿用单组关系，删除后设备进入未分组。后续变更会使旧撤销失效，避免覆盖新操作。布局适配小窗口及系统文字缩放。

主要实现位于 `flutter/lib/common/widgets/saved_devices_browser.dart`，真实数据适配与地址表单位于 `lan_workspace.dart`，批量持久化及迁移位于 `favorite_group_model.dart`。移动布局继续使用原有入口。

## 地址与身份

设备菜单及详情提供编辑地址，支持 IPv4、IPv6、主机名和端口。保存更新同一指纹的记录，保留收藏、名称与分组，将可达状态重置为未检查，并提供带版本校验的撤销。自动更新默认开启，手动修改不会隐式关闭 mDNS；关闭开关则固定手动地址。

`src/lan_devices.rs` 使用客户端 LocalConfig 的 `lan-device-addresses` 保存指纹到地址及元数据的映射。仅同指纹的有效在线发现结果可以更新自动地址；手动修改前缓存的发现结果不能立即覆盖新地址。不同指纹允许暂存相同地址，以支持 DHCP 重分配和地址互换，绝不按 IP 或名称合并。连接优先尝试保存地址，握手指纹与预期不同则拒绝该候选，在发送登录凭据前终止。

旧收藏、别名和分组仅通过已认证连接历史或既有信任绑定迁移；新设备出现在旧 IP 上不能取得旧记录的关联。发现公告本身不作为旧地址所有权的证据。既有凭据身份存储继续按指纹工作，不向新地址复制旧地址凭据。未修改 `libs/hbb_common` 或网络协议，也未增加依赖。

独立设计原型保留在 `prototype/`，仅作为选图及交互参考。客户端采用最新指纹要求，允许缓存地址重复，与早期原型的地址冲突阻止策略不同；原型不代表客户端数据实现。

## 验证

- 101 项 Flutter 相关测试通过，包含四个来源切换的几何位置一致性、96 台设备跨页移动、批量单次写入、撤销、旧键迁移、指纹规范化、写入失败回滚、地址表单及小窗口/文字缩放。
- 6 项新 Rust 注册表测试通过，覆盖同指纹改名换址、不同指纹同地址、发现不能认领旧关联、手动地址与新旧 mDNS、固定地址及无效输入。
- 7 项原有 LAN 测试通过。Rust 库、macOS Debug 客户端构建及临时应用严格签名检查通过。目标 Flutter 静态分析无错误和警告，保留风格及弃用 infos。
- 独立便携测试配置中的 96 台设备，已验证收藏、84 条分组关系和别名迁移到指纹键。原生批量移动三台设备与撤销，数量和关联均正确；手动地址保存与撤销后读取落盘配置，指纹、分组及数量保持一致，自动更新仍开启。

日志位于 `target/grouping-*.log`。预览应用为 `target/grouping-preview-final/SubnetDesk Grouping Preview.app`，配置隔离于旁边的 `userdata`，使用 TEST-NET 示例设备，不修改日常客户端数据。

Windows/Linux 尚未原生点验；真实 DHCP/mDNS 网络切换未做实机验证，相关顺序与身份规则由 Rust 测试覆盖。最终视觉验收状态见仓库根目录 `design-qa.md` 本轮记录。
