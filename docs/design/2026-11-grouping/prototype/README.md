# SubnetDesk 2.0 分组交互原型

原型保留设计选择过程。用户随后授权客户端实施，并要求以指纹作为唯一键、所有桌面来源标签保持同一布局；实际实现与验证见 [IMPLEMENTATION.md](../IMPLEMENTATION.md)。客户端允许不同指纹暂存相同 IP，早期原型的地址冲突校验不作为最终规则。

用户选择第一版「分组目录＋设备表格」。面向管理九十多台设备的桌面用户，用 96 台示例设备演示查找、筛选和批量整理；这是独立前端原型，尚未接入 Flutter、真实设备或本地配置。刷新恢复演示数据，初始三台勾选用于还原选中的设计稿。

## 页面与交互

- 顶部沿用主导航，左侧仅为收藏页的分组目录。固定「全部收藏」「未分组」，分组名称与设备总数始终对应；分组搜索用于分组较多时定位。
- 设备表格同时展示名称、地址、所属分组和可达状态。搜索匹配名称、IP、备注，输入框明确当前范围；组内搜索无结果时可保留关键词切换到全部收藏。
- 每台设备保留单一分组。表头全选只选当前页，翻页保留勾选；切换分组、来源、关键词或状态时清空选择，防止对隐藏的旧选择误操作。
- 移动弹窗支持搜索目标分组，展示目标分组移动前后的数量；已在目标组的设备不重复计数。操作完成后更新各组数量，并提供一次撤销。
- 新建与重命名校验空名称、重名和 32 字符上限。删除分组前展示影响数量，设备归入「未分组」；可撤销删除。
- 保留「未检查」「可达」「暂不可达」三种状态。添加设备默认未检查，连接入口说明原型边界，不伪造连接成功。

## 设备地址变化

设备详情提供「连接地址 → 编辑地址」，预填旧地址，支持 IPv4、IPv6 和主机名，校验格式与地址冲突。保存更新同一设备记录，保留名称、分组、备注和自动更新设置，地址来源改为「手动修改」，可达状态回到「未检查」；支持撤销。取消编辑不写入。

「允许 mDNS 自动更新地址」默认开启；手动改地址不会隐式关闭它。开启时，后续发现并核实为同一设备的新地址可继续更新；关闭时保留手动地址。原型只演示此策略开关和手动更新，没有实际 mDNS 事件。

原生落地应把设备的稳定记录标识与可变地址分开：名称、分组、备注、凭据关联到原设备；已核实的设备身份用于把发现结果合并到原记录。若当前记录以 IP 作为键，需要迁移关联关系，不能直接新增记录或把凭据自动交给新地址上的未知设备。连接仍须执行既有身份核对；地址变化本身不代表身份核对通过。

## 小窗口

桌面表格独立滚动，表头、批量工具栏和分页持续可达。较窄窗口收起重复的分组列，连接操作可通过设备详情进入；极窄屏仅作退化适配，横向滚动表格，不代表最终移动端设计。分组菜单支持键盘聚焦，弹窗支持 Escape 与焦点恢复。

## 后续落地到 Flutter

复用 `FavoriteGroupModel` 的现有单组关系和持久化格式。批量移组需要增加一次写入的批量接口，避免对 90 台设备逐个写配置；删除组继续保留设备。分页仅为原型浏览方式，原生实现可用惰性列表与固定表头，无须更改网络协议或 `hbb_common`。

接入时还需处理持久化失败、应用重启、真实设备状态、跨来源设备去重和实际键盘/屏幕阅读器行为。当前原型中的「最近连接」「附近设备」用演示数据筛选展示，无真实发现或历史记录能力。

## 运行与证据

在本目录安装依赖后运行 `npm run dev -- --host 127.0.0.1 --port 4178 --strictPort`。`npm run build` 生成静态产物。当前任务已启动本地预览。
